02 / PROBLEM

When input changes query structure

SQL injection occurs when an application combines untrusted values with executable query text. Our system inspects request inputs and compares two detection methods.

Primary defense: prepared statements with parameter binding. Detection is supplementary.

03 / OBJECTIVES & RELATED WORK

One problem, two methods

  • Implement, explain and compare both detectors.
  • Measure quality, false positives and processing cost.
  • OWASP informs prevention guidance; pattern-matching research motivates signature detection.
  • References and full source links appear in report.md, Section 20.
04 / APPROACH 1

Explicit signature rules

Bounded URL decoding → lowercase and whitespace normalization → comment handling → six rule groups.

  • Boolean conditions and UNION queries
  • Stacked commands and delay functions
  • Quote comments and metadata extraction

Verdict comes with named matching rules.

05 / APPROACH 2

Learn from character patterns

Training labels → bigram/trigram counts → smoothed class likelihoods → log-score comparison.

Multinomial Naive Bayes learns from data. It uses no signature verdicts as features. The attack score is uncalibrated.

06 / ARCHITECTURE & DEMO

A local, auditable lab

Browser → validated HTTP input → two independent detectors → verdicts and explanations.

Python standard library only. Input is never executed. Run python app.py and open http://127.0.0.1:8765.

Demonstrate an attack, a benign apostrophe, and a method disagreement.

09 / COMPARISON

Rules lead within this scope

Rules are easier to explain and faster in the local run: approximately 0.0065 ms/input vs 0.0383 ms/input for ML.

ML falsely flags sleep advice and misses DELETE and comment-obfuscated families. Training coverage and context matter.

The selected corpus does not establish universal superiority.

10 / SECURITY & LIMITATIONS

Know what the evidence supports

  • Local text inspection; no database execution
  • Small synthetic dataset; no deployment traffic
  • Correlated samples and development feedback
  • Approximate syntax handling and uncalibrated scores
  • Single-run latency; development HTTP server
